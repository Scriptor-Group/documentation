# Version 1.3.6 → 1.3.7

---

## ✨ Nouvelles fonctionnalités & améliorations

- **Connecteur Magnolia — FAQs** : si l'instance Magnolia expose un endpoint de FAQs, une racine « FAQs » apparaît à côté de Pages et Assets dans le dialogue d'import :
  - chaque FAQ est importée en un fichier par langue traduite ;
  - une traduction ajoutée dans Magnolia est importée à la synchronisation suivante, une traduction retirée est supprimée de la base ;
  - les filtres du connecteur peuvent s'appliquer aux FAQs.

  Sans cet endpoint, le connecteur fonctionne comme avant.

- **Connecteur Magnolia — liens sources** : une nouvelle section « Liens sources » des réglages du connecteur reconstruit l'adresse publique des pages, des assets et des FAQs, pour que les réponses citent la page d'origine sur le site. Les modèles d'URL acceptent des variables (chemin, langue, champ de la FAQ). Les fichiers déjà importés reçoivent leur lien à la synchronisation suivante, sans réimport.

- **Connecteur Magnolia — HTTPS par défaut** : un domaine saisi sans protocole est désormais appelé en HTTPS, et non plus en HTTP. Une instance Magnolia qui ne répond qu'en HTTP doit voir son domaine préfixé par `http://` dans les réglages du connecteur ; sans cela, sa synchronisation échoue après la mise à jour.

## 🛠️ Corrections de bugs / sécurité

- **Fix — Connecteur Magnolia, suivi des éléments** : sélectionner de nouveaux éléments dans le dialogue d'import retirait de la base ceux choisis lors d'une session précédente (ajouter un asset faisait disparaître les pages déjà importées). La sélection s'ajoute désormais à l'existant ; seuls les éléments décochés sont retirés.

- **Fix — Connecteur Magnolia, dialogue d'import** :
  - l'import d'un gros volume (toutes les FAQs, par exemple) n'échoue plus sur un délai dépassé : il se poursuit en arrière-plan et les fichiers apparaissent au fil de l'import ;
  - le retrait du dernier élément suivi peut être validé, le bouton « Importer » restait inactif ;
  - le bouton de synchronisation complète est retiré : pour un CMS, il supprimait les fichiers sans rien réimporter. Pour tout importer, cocher les dossiers racines.

- **Fix — Agents** : associer une base de connaissances volumineuse à un agent pouvait afficher l'erreur « Failed to fetch » alors que l'association aboutissait. L'enregistrement répond immédiatement et la synchronisation se poursuit en arrière-plan, avec un suivi dans les notifications.
